# Shared worker contract

Read this contract and exactly one assigned M2M JSON as the two task frames.
Referenced repository evidence may be retrieved as needed; do not replay the
whole planning pack into each worker. The canonical keys follow WSP 99's external
`0102_m2m_v1` envelope. `X` is a **local documentation extension**, not a newly
implemented runtime schema. These are authored dispatch specifications, not signed
WRE executable work orders. No worker has been dispatched by creating this pack.

## Intake and execution

1. Read root AGENTS.md, applicable nested instructions, WSP 00/21/97/99 and the
   owner's README/INTERFACE/ModLog. Lock the assigned role; 0102 is the machine,
   012 is the external principal. Do not self-escalate to coordinator or signer.
2. Bind actual candidate commit, working-tree state, dependency result commits,
   owner and exact writable files. The recorded baseline is historical context,
   not permission to overwrite newer work. Isolate each coding assignment in a
   worktree. A verifier writes its result, not implementation changes.
3. Run the repository WSP 00 software gate and obtain fresh Holo owner evidence.
   If retrieval is stale/unavailable, record that limitation and use repository
   lexical evidence under the actual applicable WSP rules; never invent freshness.
   The coherence threshold is a protocol marker: record observed gate output,
   leave an unavailable measurement null, and never claim physical entanglement.
4. Apply WSP 97: retrieve evidence and governing WSPs, research the current owner,
   micro-pass, macro-pass, hard-think, dialectic sweep and first principles before
   executing the smallest owned change. Reuse before creating infrastructure.
5. Respect declared dependencies. Stop a blocked job with a precise prerequisite;
   do useful offline preparation first. Existing principal authorization persists:
   do not ask again for an already authorized concrete action. Unspecified call
   targets, account purchases and test budgets are not filled in by guesswork.
6. Preserve exact enabled contact binding, Japanese message intent, request ID,
   one durable journal, profile checks and no automatic redial. Never delete the
   journal to recover from a timeout. `submitted` and `ended` are not delivery.
7. Use existing runtime authority/signature gates for promotion. Inspect the
   `reddog_work_order_*`, `reddog_openclaw_work_order_policy_gate.py` and
   `reddog_wre_queue_verified_authority_work_order_invoke.py` owners under
   `modules/communication/moltbot_bridge/src/`. A planning JSON is not their token.
8. Consult current official provider docs before changing provider assumptions.
   Keep real contacts, messages, keys and provider payloads out of git; store
   sensitive live evidence privately and commit only redacted references.

## Ownership and validation

Coordinator owns shared README/ROADMAP/ModLog, test registry and result integration.
Workers propose those updates in their handoff to avoid conflicting edits. All
workers may produce `work_orders/results/<T>.json` in their isolated worktree;
this is the only implicit write scope beyond `S.write`. Unlisted source changes
need an explicit owner/scope binding from the coordinator, not self-expansion.

Follow WSP 6 inventory before adding meaningful behavioral tests. Run the owning
suite and required repository hooks. Do not add tests just to mirror documentation.
Record exact commands, return codes, candidate commit and important output. Live
acceptance requires real recipient/mailbox evidence, and actual microphone/model
inference must be identified separately from mocks. A failed acceptance creates
a narrowly scoped repair assignment, then re-runs the failed gate; it does not
unlock its dependents. Token budgets are planning limits, not fabricated usage;
checkpoint with remaining work if the assignment cannot fit.

Return a result using RESULT_TEMPLATE.json. Allowed states are `completed`,
`blocked`, `failed`, `partial`; the template itself is `pending`. Completion needs
all acceptance criteria and coordinator/verifier acceptance on the integrated
revision. Leave unknown evidence null. Include deliverable_summary,
edits_or_actions, wsp_compliance, tokens_used and next_best_step per WSP 21.
