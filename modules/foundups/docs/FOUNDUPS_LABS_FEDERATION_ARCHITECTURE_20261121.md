# FoundUps Labs and Federated FoundUps Registry — Architecture Decision Record
Status: PROPOSED / documentation only (2026-11-21). Principal: 012. Operator: 0102. WSP_00 / WSP_97 evidence-gated. No live implementation, affiliation, trademark adjudication or deployment is asserted.

## Pain, hypothesis and outcome
Pain: student incubators, independent open-startup communities and founders are fragmented; institutional membership can obscure individual project ownership, and closed systems make work hard to discover across cohorts. Hypothesis: shared public discovery plus separately governed program interiors and reusable compute can enable collaboration without appropriating curricula or student IP.
Outcome: FoundUps.org is the decentralized public community front door; Play FoundUps / FoundUps World is the intended public discovery Mall; lab.foundups.com is a direct-entry educational micro-FoundUp using HPC's shared shell and exact stage dimensions. Each affiliated member may create a governed FoundUp/program Mall; each student founder or founding team owns their project beyond graduation. No program or platform claims title by listing or hosting.

## Registry and identities
One stable identity per FoundUp, founder/team, program, cohort, project and publication; use existing master Fractal identity and typed relations where verified, never a parallel engine. Suggested typed edges: program CONTAINS cohort; cohort INCLUDES project; project FOUNDED_BY founder/team; project ASSOCIATED_WITH school/program; program AFFILIATED_WITH FoundUps only after explicit agreement; artifact BELONGS_TO project with independent rights and access. A project may survive and detach from its school/cohort without losing identity or ownership. Version and provenance of all claims must be retained.
Registry display statuses: INDEPENDENT_UNAFFILIATED (publicly sourced, not endorsed); INVITED_OR_PROPOSED (internal only unless approved); VERIFIED_AFFILIATE (expressly agreed and authorized); FOUNDUPS_OPERATED (governed by FoundUps). A small dog mark denotes only VERIFIED_AFFILIATE / FoundUps-operated as explicitly labeled; neutral mark for independent listings. Never infer endorsement, consent, ownership or access from a name match. Public listings require defensible sourcing, correction/removal workflow, protection of minors, and a non-impersonation policy. No public profiles of individual minors without appropriate authorization.

## Direct entry, state and stages
Every admitted program has its own canonical direct path; lab.foundups.com is the **sole planned Labs host**. Preserve HPC exact visual shell, grid, stage dimensions and single player/output surface, without changing HPC. Nonvideo program/project tile opens a player-sized interactive board (slides, text, links, approved optional video). Pinch-out expands to webpage; pinch-in returns board then tile. Explicit visible Expand, Collapse, Close/Back, Play Video and Return to Board controls, keyboard equivalents, screen-reader labels, focus restoration and reduced-motion alternatives are mandatory. Gestures must not steal native zoom, scrolling, assistive technology or embedded media gestures; accessible controls are primary. Swiping board away restores underlying grid, exact tile, scroll, filter, query and selection. Selecting a video replaces the content of the same output surface, never opens a second stage/player. Back from video restores board and its slide/scroll; Back from board restores caller tile/grid; Back from full page restores board; auth success/cancel preserves a validated caller token and returns to authorized state or safe public fallback. Direct links with no caller return to the program wall. No protected payload is prefetched to public clients.

## Auth and ownership
Separate platform membership from program-scoped roles and project-scoped roles; an invite to FoundUps does not admit the user to every program. Existing invite-code/sign-in gate remains; no new password gate or bypass. Server-side authorization on each private API, document, media asset, write and listing; never rely on UI-only concealment. Invite issuance, verified program affiliation, content publishing, student enrollment and project editing are distinct authorities. An invited affiliated member can create a FoundUp/Mall after existing authorization and governance checks; membership alone is not automatic publication authority. Project founders retain rights; cofounder shares and school permissions are explicit. For minors, require appropriate guardian/institutional permissions and safe defaults, including private drafts, moderation, no public sensitive student information, and export/continuity after leaving. Do not treat an email one-time code as proof of legal ownership of a business or project.

## Curriculum and affiliate independence
Sachin's independently operated eight-week student incubator is a proposed reference model, not FoundUps-owned knowledge, an existing agreement, a verified media asset or an appointed leader. Preserve his attribution, ownership and ability to decline. Only agreed program structure and licensed materials may be imported. Likewise, Israeli Open Startup and other third-party initiatives may be listed accurately as independent, not represented as affiliates without consent. Trademark history does not automatically grant ownership of another party's curriculum or organization.

## Discovery, rating and future economics
Public catalog search by program, year, cohort, category, founder-approved title and lifecycle (past/present/active), with source and update timestamps. Authenticated, program-authorized project publishing and moderated community ratings are separate future phases; prevent brigading, avoid ranking minors, retain consent and appeal paths. BitClout is a conceptual precedent for discoverability, **not** authorization to tokenize, trade identity, sell claims, or represent an unconsenting founder as a tradable asset. Any economics require independent legal/consent review.

## Obstacles and governance
Risks: personality conflicts, misleading affiliate status, IP ownership disputes, minors' privacy, stale listings, claim fraud, cross-program permission leakage, vendor model/speech availability, Fractal graph maturity and HPC regression. Mitigations: consented affiliation contract, independent owner and attribution fields, explicit program admin and moderation, correction/removal, no automatic rights transfer, revocable access with data export, evidence provenance, scoped RBAC/ABAC and audit logs. A dispute freezes status changes but does not silently delete history.

## Implementation acceptance / WSP_15 order
P0: audit canonical identity, shell, caller restoration, existing auth and catalog; map source/version and blockers.
P1: public Labs directory and project board on shared stage, public STEM US, direct-entry and exact Back/keyboard/touch behavior, no HPC changes.

No implementation, hosting, schema migration, mail or DNS change is approved by this ADR. Tests, privacy review and exact SHA CI are required before promotion.
