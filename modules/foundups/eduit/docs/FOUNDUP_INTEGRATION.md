## Existing evidence

At baseline main `453f6c3570f980a7c30364ca3727084754ff9f55`, the canonical registry
had 18 entries and no `eduit` entry. The `modules/foundups/eduit` directory was absent.
The earlier EDUIT audit specified a derived media lane, not an educational module;
its “no module needed yet” statement applied to that narrower media task.

This package now specifies the educational module without deleting, rewriting or
renaming those legacy media/social records. `esingularity_001` remains untouched.

## Seven template components

| Component | This slice |
| --- | --- |
| pfMALL listing | No catalog mutation. Existing legacy media lane preserved; educational app not promoted |
| PWA shell | Route family and access contract specified; no deployed pages |
| Discord | Not created or changed; adult contributor community planned, not a child learning dependency |
| GitHub | Monorepo module/docs; no separate repository required for this incubating slice |
| Sentinel | Hooks, denials and escalation specified; no agent attached |
| Stake gate | Deferred; never a prerequisite for a child to learn or receive review |
| Interior routes | EDUIT-subordinate paths planned; no shell namespace takeover |

The current monorepo onboarding protocol governs this stage; the older generic template’s
separate-repository checklist is not used to force premature externalization.
Public landing information and learner access must remain distinct from privileged
operator/governance access. Platform stake policy must not leak into learner enrollment.

## Promotion and rollback

Advance registry/runtime labels only with actual evidence. No DNS, domain, catalog,
social publishing, payments or scholarship contact is activated. A specification change
can be reverted without touching the old EDUIT media lane or eSingularity infrastructure.
Before runtime integration, run current schema/loader/AI-hooks checks in the exact
repository checkout and complete the actual bootstrap/admission requirements.
