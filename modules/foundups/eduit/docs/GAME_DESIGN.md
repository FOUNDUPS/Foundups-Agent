# Game design and historical placement method

Status: proposed design. Historical basis: OBVC/OBVM/widget eGames in S03 and GuiGame,
placement testing, and short content units in S04. This does not establish effectiveness.

## POC game: visual pattern-rule exploration

The learner sees a demonstrated rule, tries a practice example, and selects the next
item or constructs a valid continuation. Start with clearly specified relationships
and deterministic answer keys. Provide shape/label alternatives where color is used,
keyboard/switch-friendly equivalents to dragging, captions or text alternatives to
sound, and no speed-based ability penalty by default. Difficulty levels are explicit
content-design labels, not age-equivalent or IQ units.

Record item/version, selected action, correctness against the declared answer key,
help requested, mode, input adaptation and any invalid/interrupted outcome. Explain
feedback. Allow pause, skip, retry, and leaving without punishment. Do not use streak
loss, variable financial rewards, or public child leaderboards to force engagement.

## Placement versus learning versus measurement

Placement chooses a comfortable starting point. Practice teaches and gives hints.
Measurement uses frozen calibrated material under a declared protocol. Improvement
on practiced items must not be called transfer or general intelligence.

Historical S04 algorithm: move upward on success, bracket a failure, narrow the gap.
Current candidate: cap item count and level bounds, account for help/familiarization,
stop on repeated inconsistency or learner choice, and fall back to a conservative
practice starting level. Multiple samples are required before changing a level.
Exact thresholds belong in versioned configuration and must be tested, not invented
as scientific cutoffs. An incorrect response can reflect an inaccessible interface
or misunderstanding rather than lower ability.

## Expansion after the POC

Distinct future task families may investigate spatial construction, mathematical
reasoning, causal experimentation, language learning, musical pattern creation,
and open-ended creative solutions. Each needs an appropriate construct definition,
measurement design and independent review. A pattern game does not measure all these.
Discovery should support multiple routes and repeated demonstrations rather than one
score that permanently labels the learner.

## Content-pack definition

Every pack declares objectives, prerequisites, demonstrated examples, allowed input
modes, locale/translation provenance, item/scoring versions, access adaptations,
license/attribution, asset hashes, eligibility, and approved release status.
Authoring output is data plus approved game templates, never arbitrary generated code
executed directly in a learner’s browser. Creator rewards, if later considered, must
not be tied to collecting more child data or maximizing time-on-screen.
