# Mosh Pit stakeholder surface

Status: **LOCAL_GATED_READER / CANONICAL_HOST_NOT_CONNECTED** (2026-09-09).
This is the second bounded layer of draft PR #1645. It is not deployed and is
not yet a usable posting system. No private activity or membership is in Git.

## Implemented

- `/f/esingularity_001/mosh-pit`: dynamic, Japanese activity reader; daily native
  bullets with expandable details and replies. Notes and limitations are below
  history. No fixtures, copyright notices, dashboard, or new history database.
- `/api/mosh-pit`: GET only; 401 without identity, 403 without current approval,
  503 when configuration/source is unavailable, 200 only for validated snapshots.
- Official Sites dispatch-owned ChatGPT sign-in helpers. The server derives
  identity from Sites headers, never query parameters, submitted email, or a
  client-selected role. This boundary is valid only behind Sites dispatch;
  direct access to a Worker/dev server with spoofable headers is not supported.
- Server-only, project/site-bound read allowlist, checked before upstream access.
  No owner/contributor/admin/write privileges are inferred from this read grant.
- Fresh per-request snapshots, no-store responses/fetches, explicit stakeholder
  projection only, bounded body and timeout, scope/expiry/revision checks.
  Extra upstream fields are discarded. Denial has no unrestricted query fallback.
- PWA inspection: the existing worker caches only three public icon files;
  activity pages, API responses and RSC requests are not added to its cache.

## Operator configuration (not configured by this change)

Use private server runtime configuration, never `NEXT_PUBLIC_*`, committed
configuration, or browser storage. Do not insert credentials into documentation.

| Setting | Purpose |
| --- | --- |
| `MOSH_PIT_MEMBERSHIPS_JSON` | Explicit read approvals keyed by stable **same-Site** ChatGPT user ID, with UTC expiration and policy revision |
| `MOSH_PIT_SOURCE_URL` | Full HTTPS endpoint implementing the contract below; no URL credentials, query, fragment, or redirect |
| `MOSH_PIT_SOURCE_TOKEN` | Dedicated server-to-server credential, at least 32 characters; never reuse the public webhook or resident-Memex credential |

Empty policy example (grants nobody):

```json
{
  "version": 1,
  "site_id": "appgprj_6a917b21b1a4819181a61738ed5274a5",
  "project_id": "esingularity_001",
  "revision": "initial-1",
  "members": []
}
```

Each approved member record has `user_id` and `expires_at` (UTC ISO timestamp).
Approval is an operator action; sign-in, email possession and LINE participation
do not create a record. Duplicate/malformed grants invalidate the whole policy.
Removing a grant or changing its expiration requires updating active runtime
configuration. An environment allowlist is **not** an instant revocation service:
old deployments may retain old configuration. The canonical host must check
current membership/revocation and reject stale policy revisions on every read.
Do not activate private reads until that independent host check exists.

## Required canonical host contract

The Site sends a POST to the configured endpoint over HTTPS with a dedicated
Bearer credential. Its JSON body is `mosh_pit_gateway_read.v1`, containing:

- `site_id`, `viewer_id`, `membership_revision` derived on the server;
- fixed `foundup_id: esingularity_001`, `disclosure_class: stakeholder`,
  `timezone: Asia/Tokyo`, `limit: 50`;
- a fresh opaque `snapshot_id` generated by the Site for this request.

The host must authenticate this specific Site gateway before accepting its
viewer assertion, independently validate current approved membership and policy
revision, and map the Site-bound viewer to its verified canonical principal.
`viewer_id` is **not** the breadcrumb owner's `principal_id`: the canonical host
resolves the permitted owner/project dataset. Neither field may come directly
from an untrusted browser. A bearer token alone does not confer principal or
project authority. Do not route this payload into the resident disclosure API;
its signed capabilities have a different purpose/runtime contract.

Only then may the host construct an authorized immutable snapshot and call the
existing bridge-owned `query_mosh_pit()`/`project_mosh_pit()`. Reads/writes remain
owned by AgentDB/Brain/Memex. D1 must not become a parallel activity store.

Successful JSON response:

```text
schema_version: mosh_pit_gateway_snapshot.v1
site_id: exact requested Site
viewer_id: exact authenticated viewer
membership_revision: current approved revision
expires_at: aware UTC time, no more than 60 seconds in the future
projection: existing mosh_pit_projection.v1 output
```

`projection.snapshot_id` must equal the request nonce; project, disclosure and
timezone must match. Return 401/403 for denial, not a 200 empty/private fallback.
Do not log request credentials, source records or response bodies. This adapter
and its deployment are still missing; the HTTP contract is not a claim that the
existing webhook already implements it. The frontend deliberately shows an
unavailable state until a compatible, verified host is connected.

## Validation and remaining work

Tests use only synthetic identity/activity and a mocked upstream. They cover
deny-before-fetch, removal/expiration, malformed/cross-site grants, disclosure
and snapshot rejection, response bounds, field stripping and escaped rendering.
They do not prove dispatch header integrity or deployed canonical authorization.

approved principals, test cross-project denial and immediate revocation through
the deployed chain, and verify the existing Site runtime configuration.

handling, import the cleaned Doc through that owner, and implement pagination.
