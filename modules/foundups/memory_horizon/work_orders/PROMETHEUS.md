# Memory Horizon Prometheus Brief

Build our smallest credible Memory Horizon POC without requiring 012 to manage implementation.

## Outcome

A player launches a deliberately crude survival-dungeon game, chooses a character, explores, experiences unique events, and later encounters memory probes woven into play. The system records exactly what happened, when it happened, when recall was tested, the response/cue level/latency, and a transparent retention curve.

## Plan and recursive review

0102 binds current repository truth and authority, then admits dependency-ready numbered WSP 99 orders.

Workers receive:
- this brief;
- `CONTRACT.md`;
- exactly one numbered order;
- only the context/effects admitted for that order.

Independent verifier evaluates actual artifacts against predeclared acceptance. Failure produces a narrow repair order or blocked status. Do not replace missing evidence with confidence.

## Interaction model

012 -> RedDog -> 0102 -> WRE/OpenClaw -> bounded worker -> independent verifier -> 0102 -> RedDog -> 012.

012 supplies product feedback and direction. 0102 owns decomposition, routing, evidence reconciliation and integration.

## Phase 1 visual direction

Ugly-first, low-fi, mobile-first:
- text/cards/crude pixel-like art;
- four archetypes;
- hostile branching exploration;
- inventory/status;
- simple consequences;
- no copied Fear & Hunger assets/content.

## Research boundary

Use TestMyBrain/NIH/SCAT6/jsPsych as construct/measurement references, not as product UX to clone.

## Stop conditions

Stop rather than improvise when:
- authority is missing;
- current source conflicts with ticket assumptions;
- write scopes overlap;
- provider/model binding is absent;
- validation requires a medical claim;
- public surface owner is unresolved;
- the task would require modifying protected YUMORI/eSingularity scope.
