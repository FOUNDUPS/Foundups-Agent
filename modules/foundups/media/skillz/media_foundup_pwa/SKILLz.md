# Media FoundUp PWA

## Trigger

Use when 012 asks to create, revise, or audit a phone-first landing experience for a Media FoundUp.

## Contract

1. Read the FoundUp intake, outcome, scope, prototype gate, and roadmap.
2. Identify the smallest reviewable interaction and lock later features behind separate sprints.
3. Reuse existing Mall, identity, member-access, payment, and deployment owners.
4. Keep private research masters and unpublished personal-source material outside public code.
5. For real people or events, label sourced chronology, open questions, and dramatized reconstruction separately.
6. Build one responsive state model for phone and desktop; phone is the primary acceptance surface.
7. Use live HTML for titles, controls, evidence labels, and accessibility. Do not bake critical text into generated images.
8. Bind visual states to a deterministic index and support tap, swipe, previous/next, keyboard, and reduced-motion operation.
9. Preview, test every state, record failures, and request 012 review before advancing to the next sprint.
10. Extract reusable behavior only after acceptance. Do not promote rejected experiments into the template.

## Seven-state living-poster pattern

- one locked background composition;
- seven full-frame plates;
- only controlled expression, gaze, or focal changes between plates;
- one live center aperture;
- numbered navigation;
- crossfade rather than continuous video;
- later tiles and episode content remain separate gates.

## Authority boundary

This prototype skill cannot publish factual allegations, change Site access, register a FoundUp, mint tokens, activate payments, approve production, or bypass an existing membership owner.

## Completion receipt

Record exact source revision, changed files, checks, phone-review status, current sprint, blocked next sprint, and deployment/version receipt when applicable.
