# Iterate the Storytime viewer and game

Use this route for screenshot feedback, Home Screen/PWA launch, viewport sizing,
per-panel fullscreen/pinch, touch/mouse input and whiteboard defects. Keep media
production in the parent skill; do not create another editor, shell or FoundUp.

1. Retrieve the current EDUIT README, INTERFACE, ROADMAP, deployment and specific
   review receipt. Read the actual viewer, activity, launch document, manifest,
   worker and shared Mall gesture contracts before editing. Label lexical fallback
   freshness/index gaps; a historical note never proves current behavior.
2. Freeze approved media and story invariants: cast/scale/positions, palette,
   sound/word events, 15-second world clock and rescue rules. A request to remove
   a line does not authorize restaging characters. Vertical placement may express
   stylized burrow depth. Change only the layer implicated by the feedback.
3. Reproduce the actual entry path: root, manifest start URL, inner viewer and
   existing Home Screen shortcut where accessible. Compare screenshot evidence
   with source. A missing viewport is an observed defect; its exact iOS effect
   remains an inference until reproduced on that device. Do not diagnose from
   screenshot shape alone or substitute device-name sniffing for responsive layout.
4. Extend existing owners. Keep one viewer source with a deterministic standalone
   projection; reuse Mall gestureZone with a bounded platform adapter. Bind an
   expand/collapse control to each panel, preserve aspect ratio and safe areas,
   retain play/feedback controls, and suppress accidental taps during pinches.
5. Apply the ordered output audits to the changed surface. Physics/causality:
   expansion/rotation must not advance an unseen rescue. Continuity: layout changes
   must preserve media/game state and normalized feedback. Education: keep sound
   words visible and controls away from them. Readability: inspect real panel and
   control bounds at phone/tablet portrait/landscape sizes. Keep browser zoom usable
   outside dedicated panel gestures. If media is untouched, retain its identity
   and prior auditory limits rather than claiming a new listening review.
6. Repair -> preview -> inspect -> grade with a fixed, scoped rubric. Exercise
   actual expand/collapse, pointer marks after resizing, pinch cancellation,
   safe message origin, launch asset paths and packaging CLI. Event simulation
   proves callbacks, not physical iPhone touch delivery. Record PASS/FAIL/UNVERIFIED
   separately for source tests, browser viewport checks and real device acceptance.
7. Obtain independent review, repair its findings, and recheck the affected path.
   Preserve failed attempts and source identity. Retain a useful correction as a
   candidate skill improvement; forward-test it on the next actual episode when
   applicable. A documented procedure is not autonomous RSI or model training.
8. Bundle the accepted source, module docs, skill correction and evidence into
   one milestone PR. Pass applicable checks, squash-merge, deploy that source and
   verify the exact live root/inner routes. Do not create a PR per visual tweak.
   Do not re-upload an unchanged video or activate WRE for a direct UI repair.
